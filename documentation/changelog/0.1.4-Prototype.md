# Changelog: 0.1.4-Prototype

## CHG-0282 · 2026-11-14 · Agree on browser access and a host apart from Electron

Type: Documentation
Event: Agreement
Scope: Architecture, host lifecycle, browser access

Summary: The owner agreed that the shared interface and host must not require Electron, browsers must reach a host without installing anything on their device, and the host may keep running after the desktop app quits. Iskios's code stays TypeScript with Effect and one Expo interface; no Rust migration. Four access requirements record browser access, no additional networking tools, an independent host lifecycle, and feature parity. The owner prefers Bun if it fits; the recorded macOS Bun probe failed at SQLite extension loading, so the runtime decision follows in CHG-0283.
Reason: Reach the same host from any device, without a separate backend per client.
References: [0017](../architecture-decision-record/0017-typescript-and-effect-no-rust.md), [requirements](../requirements.md#access), [backlog](../backlog.md).
Validation: The owner's first-round answers in this thread. Documentation only; no implementation claim.

## CHG-0283 · 2026-11-14 · Agree on host lifecycle, remote terminals, and host-side updates

Type: Documentation
Event: Agreement
Scope: Architecture, terminals, updates, naming

Summary: Node runs the host independently, using the desktop binary as Node in packaged builds. A per-user login service supports Keep running after quitting; a lock and private endpoint/token file serve local clients without changing persisted remote pairings. Optional sleep prevention applies while turns run. Terminals move to the host with OS confinement for paired devices. Updates run through the host and restart Iskios, not the computer. The relay serves release-matched web builds; clients of another release are refused. Desktop, web, and mobile apps share the Expo base. Tauri is excluded. New requirement: Updates keep the host reachable.
Reason: Keep an unattended host usable from a browser without losing its features or requiring another sign-in after updates.
References: [0018](../architecture-decision-record/0018-host-service-runs-on-its-own.md), [0019](../architecture-decision-record/0019-browsers-use-the-relay-served-web-app.md), [0020](../architecture-decision-record/0020-terminals-run-in-the-host.md), [Paseo research](../research/paseo-daemon.md), [glossary](../glossary.md#devices).
Validation: The owner's second-round answers. Sleep prevention being on by default and failed-update rollback are agent recommendations recorded in the design, not separately confirmed product decisions. No implementation or cross-platform verification is claimed. Browser code delivery trust remains open.

## CHG-0284 · 2026-11-14 · Keep Electron for now without Electron-only features

Type: Documentation
Event: Agreement
Scope: Desktop shell, future branding

Summary: Electron stays for now to ship Node and a desktop window, while its features move into the host or gain web equivalents. The inventory is in 0018; a no-shell desktop and Electrobun remain later comparisons. Separately, the owner requested a future app rename to Outlore; Iskios remains a theme with its icon. The rename is a backlog item only.
Reason: Preserve current functionality across clients without coupling it to Electron.
References: [0004](../architecture-decision-record/0004-electron-desktop-shell.md), [0018](../architecture-decision-record/0018-host-service-runs-on-its-own.md), [backlog](../backlog.md).
Validation: The owner's Q19 clarification and subsequent Outlore request. No application name, identifiers, icons, or source code changed. Entries were moved from the unreleased working copy of 0.1.3 and renumbered after origin/main published that release with its own CHG-0280 and CHG-0281.
