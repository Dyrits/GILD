After · one module, two questions and one note

Callers keep only the tool; the refusal wording and the grant sit with the rule.

Problem. The rule for who may message or read whom is decided in three places and announced in a fourth, and mentionNoteOf promises what readTurnReach grants, so the promise and the grant can drift apart.

Solution. Put the tree rule, Iskios's rule and the turn grants behind one module; mentionNoteOf reads the same resolved grants the handlers check.

  • locality: reply-rule changes (the specification review's P4 and P5) land in one file
  • leverage: one interface, two tools and the note
  • tests cross the interface: tree, mention and sender cases together
  • queries stop repeating per tool call
Settle the open specification points P4 (deleted sender) and P5 (reply rule wider than agreed) first: the module would encode whichever answer the owner gives.

Problem. What a mention looks like (icon, label, token, “no longer open”) is worked out in two modules, and ChipText must know which of two loaders owns each token.

Solution. One module resolves a mention from either source and both the menu and the chips read its result; the specification review's P7 wording is then fixed once.

  • locality: chip wording lives in one module
  • leverage: one resolver, menu and chips
  • chipsOf takes one input, not four
  • tests need no screen and no loader
Overlaps B in controls.tsx; do B first, then C reads one interface.

Problem. The theme is a string literal copied across the app and the desktop shell, and its Dock sync fails silently (the standards review's S1); colorScheme.ts also carries the place-resume mechanism for reloads.

Solution. Put the choice, its persistence and what it selects behind one module; the desktop adapter takes the shared type, and a failed Dock sync is handled in one place.

  • locality: a third theme is one change set
  • the hand-typed theme literal goes
  • S1 gets one owner
  • tests cross one interface
Only one theme pair exists today, so the seam is partly hypothetical, and the owner wants a matte rework of the Gild icons (backlog) that will move these files anyway. Wait for it.
