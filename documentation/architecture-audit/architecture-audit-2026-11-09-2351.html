Problem. The app guesses path equality and folder names that the service already resolves properly; createRealm returns null, and on an existing folder the typed name and crest are dropped. Symlinked and suffix-sharing paths are misjudged.

Solution. The service owns folder-to-realm resolution and returns the realm; identity crosses the seam as an id.

  • locality: one path rule, in the service
  • delete samePath and folderNameOf
  • tests use temporary folders and links
  • consistent with decision record 0002
