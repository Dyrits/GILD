# One theme and staying in Look and feel

## Verdict

One is selectable alongside Iskios and Gild, using the existing Light / Dark / System preference.
Theme and appearance changes return to Workshop → Look and feel after the reload.
Both looks and system-following were exercised in a throwaway Electron window; the owner's visual acceptance is pending.

## Scope and source

- Starting revision: `fd4680e`; implementation: `875699a`.
- Zed's published One Light and One Dark palettes, with [pinned source, license, and mapping](../research/zed-one-themes.md). No Delta code copied.
- Existing Iskios/Gild colors and the default theme are unchanged.
- One uses Iskios's application icon and the existing shared sidebar drawings.
- The MIT notice is retained at `apps/desktop/assets/one.LICENSE`; the packaging file explicitly includes it. An installer was not built or inspected.

### Navigation bug

The first `stay-in-look.js` run, before the fix, timed out waiting for the Theme group after choosing a new theme.
The app had returned to Settings but showed Permissions.
Reading `App.tsx` confirmed that its initial section was always `"permissions"` even when the existing appearance flow supplied `resumedPlace === "Settings"`.

The fix initializes that section through `settingsSectionOf(resumedPlace)`.
Only theme/look reloads set the resume marker; normal Workshop navigation still starts at Permissions.
The same Theme-group assertion passes after the fix, with the selected theme retained in local storage.

### Both looks and System

`check-one.js` passes after the fix. It:

1. Selects One through the actual Theme control.
2. Chooses Dark and Light through Appearance, checks that the Look and feel controls remain visible, and checks the actual root scheme/background and selected theme button's accent against the palette.
3. Captures Look and feel and Guild Hall in each look.
4. Chooses System with an emulated light OS, changes the emulated OS to dark, and verifies that the app reloads into One dark with System still stored and Look and feel still open.

## Limits

- Not checked: an installed/package build, Windows/Linux, native phone builds, a paired host, a narrow window, or every screen in both looks.
- Conversation bubbles and state labels have palette-level contrast checks, not a conversation-window drive.
- The existing xterm palette mapping is reused; this is not a complete port of Zed's ANSI or syntax-highlighting system.
- Source adaptations are documented in the research note; the light accent is a darker Zed blue for contrast rather than an exact copy of its UI accent.
- Screenshots and a passing browser script do not constitute the owner's visual acceptance.
