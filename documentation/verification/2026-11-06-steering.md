## Evidence

- **C1 to C6:** `bun run test` passes 102 with 5 skipped. Shown able to fail with [mutations.sh](2026-11-06-steering/mutations.sh), run in a disposable worktree holding the working tree: each of the 8 mutations failed between 1 and 5 checks, and the restored tree passed 102 ([mutations.txt](2026-11-06-steering/mutations.txt)).
- **C7:** `OPENMISSION_LIVE_CLAUDE=1 bun run test` passes 107 of 107. The interrupt check first asked for `sleep 60`, which Claude Code refuses as a standalone sleep, so the turn ended before the interrupt; it now runs a one-second tick loop and passed in three further runs.
- **C8:** Settings show "Send, while a thread is running" with Steer selected ([settings-delivery.png](2026-11-06-steering/settings-delivery.png)). A mission running a 40-second fake turn showed Interrupt, Queue, and Send; "Also mention the README." sent with Send appeared plain, and "Afterwards, summarize." sent with Queue appeared as "You · Queued for the next turn" ([steer-and-queue.png](2026-11-06-steering/steer-and-queue.png)). Interrupt made the thread Idle within 4 seconds with no reply from the interrupted turn, the queued message started the next turn ("Echo: Afterwards, summarize."), its mark cleared, and the extra buttons disappeared ([after-interrupt.png](2026-11-06-steering/after-interrupt.png)). With the default set to Queue, a running thread showed Interrupt, Steer, and Send, and the placeholder "Send waits for its next turn" ([default-queue.png](2026-11-06-steering/default-queue.png)).

## Not verified

- The window with a real Claude Code turn being steered or interrupted (session limit); C7 covers the same service path without the window.
- A steered message that Claude Code takes in just as the process closes, which the model would then see twice (provisional in work-in-progress, Batch 6).
- An interrupt Claude Code does not confirm within 10 seconds; the fallback that closes the process has no check.
