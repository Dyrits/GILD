## Evidence

### C1 to C9: service checks

- **Check:** `bunx vitest run packages/service/test/rituals.test.ts packages/service/test/ritualSchedule.test.ts` (16 tests), on the fake harness whose `fail <harness> <reason>` line fails a turn on that harness, with a test clock for the scheduler.
- **Shown able to fail** (mutations in the working tree, each restored):
  - no fallback call after a failed turn: the three fallback tests fail (C5, C6);
  - an unlimited grace for missed runs: the missed-run test fails (C8);
  - `>=` for `>` in the next-time search: the daily test fails (C1);
  - no return to the primary Companion at a run's start: the primary-again test fails (C6);
  - no refusal for a thread in a turn: the refusal test fails (C4).
- **Not shown able to fail:** dropping the `is_on` filter in the scheduler's query changes nothing, because an off Ritual also has no next time; the two rules overlap.
- **Result:** 16 passed.
- **Defect found by the full suite:** a first scheduler that woke every 30 seconds made the tests that move the clock by months time out (nine tests). It now sleeps until the next Ritual is due and wakes on any change, as the budget-period layer does.

### C10: the running app

- **Check:** `serve.ts.txt` (the service on the fake harness, endpoint printed), the web export served on 8099, and `drive.py`: opens the Rituals category, "+ New Ritual", fills a title and an instruction (`fail claude Usage limit reached` then `runner`), adds a fallback (Codex), creates the Ritual, returns to the Rituals place, presses Run now, opens Quests, then opens the Ritual from the rail.
- **Result:** `RAIL_HAS_RITUALS True`, `CARD_SCHEDULE True`, `RUN_LINE True`, `FELL_BACK True`, `CRUMB_RITUALS True`. [Form](2026-11-10-rituals/01-form.png), [Rituals place](2026-11-10-rituals/02-rituals-place.png), [Quests board with no Ritual](2026-11-10-rituals/03-quests-board-without-ritual.png) ("No quests yet." in the rail), [the Ritual's quest under "Rituals › Morning digest"](2026-11-10-rituals/04-ritual-quest.png) with "Ritual · run by you", the line "Fell back to Codex ... · Usage limit reached", and the Codex reply.
- **Weak probe:** `RITUAL_NOT_IN_QUESTS_BOARD` in the script is always true (it ends with `or True`); the evidence is the screenshot and C11.
- **Defect found by driving:** the panel of a Ritual's quest offered Mark as done and Archive; archiving would have hidden the Ritual from every list, so the panel hides them for a Ritual.
- **Awaiting human judgment:** how the Rituals place, the card, the form, and the rail row look.

## Reproduce

```sh
bun run typecheck && bun run check && bun run test
bunx vitest run packages/service/test/rituals.test.ts packages/service/test/ritualSchedule.test.ts apps/app/test/ritualLabels.test.ts
```

The window drive: copy `serve.ts.txt` to `packages/service/scratch-serve.ts` and run `GILD_DATA_DIR=/tmp/gild-ritual ELECTRON_RUN_AS_NODE=1 ../../node_modules/.bin/electron scratch-serve.ts > /tmp/gild-serve.log` from `packages/service`; export and serve the app (`cd apps/app && bunx expo export --platform web --output-dir /tmp/gild-export`, then `python3 -m http.server 8099` in it); create `/tmp/gild-drive`; run `python3 drive.py`. Delete the scratch copy afterwards.
