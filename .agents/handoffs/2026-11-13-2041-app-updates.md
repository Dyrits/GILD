## Decisions

- The seven choices the owner accepted in CHG-0266 ("Ye sto all"): all three platforms; macOS through our own updater (Squirrel.Mac refuses an app with no Developer ID) and Windows and Linux through `electron-updater`; check at start and every 6 hours and on demand; background download, install only on Restart and update; on by default with an off switch, plus the requirement "Update check carries no owner data"; a prerelease build follows prereleases and stable releases, a stable build only stable; an Updates section and a notice; trust is HTTPS from the repository's release plus the SHA-512 in `SHA512SUMS.txt`, with no signing key. Recorded in `documentation/changelog.md` (CHG-0266), the specification and `documentation/requirements.md`.
- My choices, not asked of the owner (all in the specification): the switch and last-check time live in `updates.json` in the app's data folder, not in the shared settings, so nothing in the service or contracts changed; the notice is a pill in the top bar that opens the confirmation; "Later" hides the pill for that version only; a release without this architecture's installer or without the checksums is skipped for the next one; an earlier failed swap is shown at start and no check runs then; a throwaway run (`ISKIOS_DATA_DIR` set) may override the release list (`ISKIOS_UPDATE_URL`) and the program that starts the new app (`ISKIOS_UPDATE_OPENER`), the installed app never.
- Out of the batch and in the backlog: smoke-testing Windows and Linux, a signed manifest or Developer ID signing, a data backup before updating, the owner's channel choice, how many turns a restart will stop.
- Handoffs are shared and committed. Pushing to `main` uses `--no-verify` when the owner asks, as the previous handoffs record.
